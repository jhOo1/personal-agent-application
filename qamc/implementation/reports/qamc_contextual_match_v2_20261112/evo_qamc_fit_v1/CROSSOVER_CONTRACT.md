# The fixed-plan crossover changes only final historical exposure

For all 40 assigned tasks, the parent final-Actor request existed and the Self-ReCheck selected packet was available. The 39 new request bodies retain the task-first parent system instructions, final model, sampling properties, token cap, current task and exact plan. The only changed field inside the user payload is the ordered original-source list. One formal message has the exact same full retained input and reuses its task-first output and score. The auditor verifies request hash equality against local transport receipts and zero retries. [Request audit counts](CROSSOVER_CONTRACT.json)

The key comparison is the task-first parent versus the crossover. On the manager-and-coworkers lunch case, the parent plan never received the requester's personal efficiency preference but the actor in both arms can still see it: Self-ReCheck retained that source. This pair can show whether removing all other history changes the influence of the retained source. It cannot test what happens when this source itself is removed. On the tax-discrepancy case, the crossover sends empty selected history; the task-first parent received all candidates and scored AAR 1, MR 0, completeness 4. Check whether the resulting message still implements concise expression and maintains its required request. These are case-level predictions fixed before crossover scoring, not performance claims.

Three source sets are held distinct in reporting: original candidates, sources admitted by Self-ReCheck, and the sources actually passed to the final generator. Original author labels and task attributes remain evaluation-only.
