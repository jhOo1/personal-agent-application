# Shared first-pass Actor search

The pinned transfer found that source-selection lift largely disappeared under the specialist Actor variants. The specific target is how a shared Actor turns retained evidence into a decision criterion, binding requirement, useful choice or expression in a completed deliverable. One related anecdote can regain an inappropriate influence after the most obvious private belief is hidden. The new trial replaces the entire system instruction for the same shared single-call Actor. It does not add a policy block to three specialist systems, control plan visibility, choose a better answer after generation, or classify history again.

## Initial fit round

The ordinary and paired criteria search use one proposal each, with the same model, two parent system instructions, proposal ceiling and raw historical fit records. They see the same seven record pairs and score fields. Tasks and history are shared by reference to avoid duplicating long inputs. Both can inspect both real answers. The ordinary control sees task-indexed individual traces. The structured arm sees explicit pairs and instructions to distinguish ranking, actual constraints, expression and claims from mere mentions. The fit feedback includes different generation pipelines and potentially different visible evidence. Its differences are comparative feedback, not isolated effects. Both output one whole general Actor instruction, with size, literal reuse and benchmark identifier checks. This is a controlled full-prompt search step inspired by reflective optimization, not an author GEPA implementation or a completed multigeneration search.

The compact fit round includes 12 already exposed tasks, four distinct groups per benchmark. RPEval and PersistBench each cover their three existing task strata. Selection within quotas uses frozen UID hashes, not new scores. Both search proposals and the shared handwritten seed run once on both previously executed raw-source conditions. Their current task, facts, task-only plan, precise memory and model settings remain identical to the original Scope requests for the same source condition. Selected inputs are reconstructed and verified against the recorded Scope-flight hash. The system instruction is the only changed field. Offline case material and opponent answers are never inserted into the Actor user message. The original Scope predecessor and specialist comparator retain their historical results.

JCC-source input is the primary fit condition; ordinary-gate source input gives a matched sensitivity check. Keep RPEval Match and OPB/UPB/FM, BenchPreS AAR/non-bold/MR/completeness, and separate PersistBench risk plus strict beneficial-use. Use equal-domain internal utility without allowing a strong aggregate to erase a substantive legal-use or task-quality regression. In a second fit round, give both search branches the same additional proposal budget. If useful, freeze the best shared whole prompt and evaluate it on the existing broad development set. The already qualified source-disjoint group panel is a rollout preflight, not an independent confirmation. It uses the existing Scope source policy, so running it without also recomputing JCC would test the prompt under a different fixed source policy.

Reserve a candidate only when its actual task behavior supports the scores, including binding preferences and task completion. Recovery of legal emphasis alone is trackable but does not demonstrate improved preference-use reasoning. Useful complementary performance can enter the fit frontier; no per-task answer picking, deployed score use, benchmark-specific Actor routing, or threshold fitting on the sealed set. All variants are API-only and training-free. The graders remain current project adapters.

Run `run.sh first-pass-fit freeze|run|report`. `run.sh first-pass-inventory` audits the later source-disjoint development roster without dispatch. The frozen initial round caps generation at 72 Actor calls and 2 proposals before exact deduplication, plus project scoring. The independent resume namespace ends in `_whole_actor_search_v1`. No automatic failed/unknown retries, and no additional selection or plan requests.
