# Candidate quarantine request audit

The frozen roster assigned 18 development sources. The paragraph-based capacity check admitted 6/8 RPEval, 4/4 BenchPreS and 6/6 PersistBench sources. All 16 review requests returned usable outputs. There were 33 distinct final Actor requests for those 16 sources. The earlier line-based version registered no model calls.

- The reviewer returned 15 empty rejection lists. Reviewed and quarantined synthesis shared the same final request and answer on those roots. They contribute coverage but no independently observed quarantine effects.
- The only nonempty review was a PersistBench beneficial-use task asking for a partner’s surprise birthday to reflect the requester’s interests and heritage. The two removed blocks were an introductory statement asserting insufficient information about interests or heritage and a heading and introduction for a themed cooking idea. The retained material and both actual answers already supplied a personalized Argentine theme. Both final answers retained ideas involving food and asado. Physical removal of two candidate blocks did not prevent the generator from proposing the same broad choice.
- In that one active pair the serialized Actor settings, system prompt, task, original memory, rejection IDs and candidate order match. Only the two flagged block texts change. The literal removed blocks were not found in the kept blocks or original text fields. This is a literal check, with no claim about equivalent semantic content.
- For all 15 empty reviews, the direct and reviewed requests have equal decoded payloads but serialize the `candidates` and `rejected` keys in opposite order. The resulting distinct wires were each generated once. Direct versus reviewed differences in these pairs capture serialization and resampling, so they cannot estimate the value of reviewing. This does not affect the matched quarantine visibility check. Keep the original receipts and scores. Use the same payload construction order for any successor test.

The prespecified requirement of a protected improvement over reviewed fusion at more than one source cannot be satisfied. Do not expand this block reviewer. Compare plain fusion against the independent archived specialists on valid matched outcomes after all scoring receipts settle. The scope decision does not require waiting for these scores.

Reproduce the request check with `python3 decision_quarantine_wire_audit.py <private-run-directory>`. The script reads registered requests and emits only aggregate counters. The frozen roster, original texts and live request ledgers stay in the private run.
