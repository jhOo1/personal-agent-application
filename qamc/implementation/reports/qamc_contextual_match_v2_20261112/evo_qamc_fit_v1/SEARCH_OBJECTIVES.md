# 三基准联合搜索的计分约定

QAMC-v3.2 复议后决定保留三基准。当前研究仍需要同时检验历史诱导的错误决策、合法记忆的收益，以及正式交付能否真正落实已送达的表达偏好。MemSyco-Bench 可提供同一偏好的合法与越界作用诊断，暂未验证它能覆盖正式文书的表达与完整度。单项失分不足以改变范围。

- 主要竞争对手是同一方法在三项上的固定输入适配。第一轮使用等调用普通规划作为内部对照。优先补作者 Self-ReCheck ID 直接选择的统一外部对照。各项专项专家用来估算余量。
- 搜索统计使用三项等权。RPEval 用 Match 比例。BenchPreS 等权平均 AAR、1−MR 和完整度的线性量表归一值，另报无完整度的敏感性。PersistBench 等权平均严格有益、跨域通过和迎合通过。探索单次风险采用单次分，同题比较双方必须使用相同抽样数。终选的风险比较优先三次。绝不把一次风险分写成三次风险结果。
- 评价使用原冻结适配 Judge。各项的原始指标和缺失照常报告。对共同有效分可计算综合差，并提供全部分配任务的可行界限。权重各在 1/4 至 1/2 且总和 1 时，最坏增益是（各项增益之和 + 最小单项增益）/4。该数不是作者原生指标。
- 候选保留等权领先者，也保留分别支配各项的候选继续试组合。任务可以改变行动，在线只读取 Query、当前事实和原始候选。任何受监督反思的真实成稿、评分和标签只用于离线候选构建。拟合集的结果只用于开发。

外部对照用作者固定提交的提示、输入形状及 ID 解析器。该选择器按作者格式只读问题和候选。最终 Actor 与两种规划策略使用同一模型、输出长度和基本交付要求，并直接接收选出的原文及原有当前任务事实。两臂规划策略则分别接收规划文本及完整原文。此对照衡量完整策略。生成及评分成本均入账。同一任务同一报文的旧成功选择仅在回执一致时复用。正式比较须再补同期稳定性和适配披露。

## 恢复入口

`bash run.sh check` 校验原两臂报文，`bash run.sh run` 使用已登记回执接续；外部对照分别用 `bash run.sh self-recheck check` 和 `bash run.sh self-recheck run`。以上命令从研究仓库内此目录运行，亦可从根目录提供完整相对路径。两批顺序运行，共用网关并发和派发间隔。已完成后用 `bash run.sh summarize --external` 读取终态并输出汇总。只公开汇总与实现。原始报文、输出、评分及请求回执在同名 runs 目录，另有后缀 `_self_recheck` 的单独目录。

## 第一批的任务先行路径

普通规划和逐决策规划在第一次调用均已看到完整记忆。看完首批规划回执、终答开始前增加一条任务先行路径。第一次调用只见当前任务、上下文和事实，第二次才把全量原始记忆与计划同时交给相同 Actor。该输入差异检验历史是否已把错误默认写进任务规划，而不依赖模型在同一次调用中遵循先后顺序。与两条原规划路径共享 40 题、模型、两次调用、长度上限、终答指令与评分。计划提示按无记忆输入作了必要调整。此臂与其他臂均属开发拟合。

接续入口为 `bash run.sh task-only check` 和 `bash run.sh task-only run`。全部批次完成后，`bash run.sh summarize --external --task-only` 读取四臂共有效结果并报告各臂覆盖率。

`bash run.sh feedback <parent> <opponent>` 从两条策略已结算的同题终答构建私有迭代材料。优先取每个基准的可修复失败、优胜保护及其他指标变化，按来源去重。材料包括实际任务、固定记忆、两份终答、原分差及已有评分旗标。材料会保留裁判可能出错的线索，仅在离线修改策略时使用。例子的任务内容和原分不作为下一版部署输入。

配对汇总同时给出所有方法共同有效结果和每一对方法的独立共同题，避免新增缺失较多的对照改变早期两臂的比较分母。全部分配界按冻结题目的原始适用位置数、误用位置数、任务完整度量表及 PersistBench 三类题数计算。某臂缺分时只为该题计入最差和最好可行值。若区间跨零，数据不足以确定全部分配任务的领先关系。

## 组合候选

RPEval 原生适配结果提示两条完整历史规划的主要损失都出现在全 A。新增候选将已经派发的两个对照交叉组合。第一次规划使用只看当前任务的现成计划，最后一次生成使用作者 Self-ReCheck 选出的原始文本。与任务先行且终答看全史的做法共享计划、Actor 和当前事实。与直接选择共享最终可见来源。组合不会额外调用规划器或选择器。新增终答和评分单独入账，部署成本仍要计入两个上游步骤。复用完全相同的终答请求及原评分时保留原有缺失或失败。两个父运行均结算后才构造候选，任一父请求不可用的任务仍留在分配分母。查看两条对照的三基准结果后决定是否派发组合候选。

恢复与验收入口为 `bash run.sh crossover freeze`、`bash run.sh crossover check` 和 `bash run.sh crossover run`。该组合实现完成时，两个父运行尚未完成。正式请求仍以完整上游回执冻结和哈希核验为准。

## 筛选后规划的配对矩阵

QAMC-v3.2 建议补齐两格。在 Self-ReCheck 已选出的相同原文子集上，复用首轮普通规划和逐决策规划的完整提示，两臂均以该子集规划和生成。与全史的首轮两臂构成规划策略和暴露范围的四格开发对照。这样能检验偏好实现收益在较干净输入下是否保留。同期采样和统计交互仍需另证。

仅在选中集合完全等于原输入时复用首轮实际终答和评分，保留既有失败。原生评分继续依据完整原始位置，筛掉的来源不能从分母消失。先完成统一外法、任务先行和组合，再推进筛选后规划。开发任务、原评分和已曝光边界沿用。

命令为 `bash run.sh selected-planning freeze`、`bash run.sh selected-planning check` 和 `bash run.sh selected-planning run`。结算加汇总开关 `--selected-planning`。

## 确定下一代父候选

`python select_parents.py <已结算的 SUMMARY.json>` 在共同有效题上比较统一方法，输出综合分领先者及各项保护指标领先者，剔除被另一方法全面支配的候选。专项参考组合留在结果表，用于衡量差距。选择某个父候选用于研发不等于证明可部署优势。仍需核对全分配区间、评分旗标及真实终答差异；空切片不产生跨基准排名。

四格结算使用 `bash run.sh factorial`。它在四臂逐题共同有效的集合上给出两种暴露条件中的规划差、两种规划中的筛选差，以及两差之差。缺分区间从同一批分配题和原始位置计算，每个空格允许各自取可行极值。指标定义、权重及父候选选择继续沿用既有约定。不同阶段生成且每格只部署一次，因此两差之差作为开发信号，不直接解释为已重现的交互效应。

`bash run.sh evolution-feedback <已结算的 SUMMARY.json>` 会从综合分领先的父候选和每个基准仍有互补优势的父候选中，提取实际已评分的胜负及保护案例。若 PersistBench 两个父候选没有等级分胜负，另外保留双方同败的迎合案例。首份基于固定计划对照与已有父候选的清单记录了 RPEval 6 条、BenchPreS 3 条及 PersistBench 同败 2 条。真实请求、答案、评分和逐题内容只保存于本地离线材料。公开文件只含来源计数、结果哈希和已公开的共同面板大小。
