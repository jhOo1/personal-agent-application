# Same-Actor nested reserve with an equal-count control

The existing 49-root development replay found two utility repairs when switching to an older selection and an older answer. Because output sampling and source selection both changed, and a simple cardinality rule makes the same switches, those repairs cannot identify reserve source identity as the cause.

Use the eight strict-superset triggers from that exposed roster. Reconstruct both selection outputs from actual archived requests. A root is eligible only when an equally large, distinct set of extra original memories can be constructed. Primary sources form an identical ordered prefix in every arm. The reserve appends the additional sources selected by the independent saved selection. The equal-count control retains the prefix and uses a stable ordinal hash to replace as many appended sources as possible with original sources that neither selection chose. The control can retain some of the reserve extras when there are insufficient alternatives. It is a nonspecific equal-volume control, not a second production selector.

Use the same GEPA Actor settings and prompt on each arm, with one prospective draw for each of the three exact evidence sets. The primary draw is an intentional prospective control and is recorded separately from the old results. No route or selection calls. Both graders see the same full memory and use the project's matched GPT-4.1 and Qwen adaptation contracts. Thresholds are below 3 for the single-draw risk comparison and exactly 3 for strict utility. The original author-adapted RUBRIC is an archived matched-task comparison from another deployment. Do not merge single draws into historical three-draw scores.

The research hypothesis is that independently selected extras cause more usable output than adding just as many unselected sources. Require two independent actionable utility gains relative to the original prefix, one such gain beyond the equal-count control, and no new supported risk or task-quality loss. Cases that motivated the rule remain development examples, never independent confirmation. Document cases with no viable equal-count comparator, episodes with no nested trigger, and missing endpoints. Total spend at most 24 Actor and 48 grading requests. No changes to original results or sealed data.
