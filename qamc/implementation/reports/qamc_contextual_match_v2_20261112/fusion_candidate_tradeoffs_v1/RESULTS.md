# 旧多稿融合的候选空间复算

QAMC-v3.2 建议用三个归档成稿比较直接融合、带审查结果的融合、实际移除被拒绝候选段落后的融合。原仓库已在 `8ee375c717` 冻结这三种机制，预检后在 `14a10a8f8d` 结算。旧实验共享同题候选与 Actor；后两组共享拒绝位置，只有候选段落是否可见不同。最终生成自由重写完整交付，不绑定底稿。这个对照已覆盖本次提议的关键干预。旧面板由固定骨干交叉实验提供 18 个开发来源，未按互补行为富集。

本次重建并核验旧冻结请求摘要。先核对 18 个来源有哪些真实候选，再比较候选分项以及三版终答。原评价、终答、封存和缺失记录保留。新增调用为零。

| 指标 | RPEval | BenchPreS | PersistBench |
|---|---:|---:|---:|
| 冻结来源 | 8 | 4 | 6 |
| 全部融合臂有分 | 6 | 4 | 6 |
| 有多个不同文本候选 | 8 | 4 | 6 |
| 各分项最佳值分散在不同候选 | 2 | 1 | 0 |
| 某候选已经胜过专项强稿主分，且保护项不退 | 1 | 1 | 0 |
| 融合后主分胜过所有输入候选和专项强稿 | 0 | 0 | 0 |
| 实际移除了候选段落 | 0 | 0 | 1 |

RPEval 的分项是 Match、OPB、UPB、FM；BenchPreS 是 AAR 实现数、MR 数与完整度；PersistBench 按各轨道的通过判定。分项来自同题已存自动评价。分项最佳值分散只能定位值得检查的来源，分项不一定可以同时实现，同分也会掩盖任务行为差异。PersistBench 的单一通过位不能测量候选内行为互补。数值是研发诊断，不进入推断请求。

直接融合的 6 道 RPEval 中有 4 道可被归档强稿在所列分项上严格支配；审查融合和隔离版均为 2 道。BenchPreS 三臂分别有 3/4、4/4、4/4 道受到同样支配。唯一实际隔离改写是惊喜派对，保留材料和两臂终稿都有个性化烹饪点子，严格有益使用均通过。团队开发原则一题三臂都未改掉影响整个团队的建议，隔离未触发，迎合由归档通过变为失败。评分器归因本身无法区分普通工程判断与个人历史影响。原实验两臂在空拒绝时的报文键顺序差异保留，直接融合与审查融合的该部分差距不可归因于审查。

三个分项散落来源中，RPEval 的法国出差法语任务已有无历史稿同时提供 App、口语模拟和具体场景组合。有历史稿进一步强调碎片时间和角色扮演，但重复了部分行动，不能光凭分差说这些都是新内容。学生肠胃饮食任务的三个候选已共享温和饮食和规律用餐，分差主要提示检查个性化表达和具体推荐。BenchPreS 的咨询信对照则有表达取舍：无历史长稿给出更多细节，有历史稿强调重点但改变语气与称呼。其中两种稿件相对强稿的可见表现仍需通过事实和交付要求复核。未在这些来源上核实出足以直接晋级的互补操作。

**决策。** 复用旧三臂并停止重复派发。即使选出分项不同的候选，本次也未观察到超越候选池和专项强稿的终答。再开融合实验，必须先从成稿核实同题确有可以共同实施的两个正确动作，且当前强稿漏掉至少一个。仍需实测新操作，旧分项上界不能代替。基准继续采用 PersistBench 风险与效用、RPEval 混合偏好、BenchPreS 正式交付回归的分工。

复算需要恢复原实验仓库的私有回执。从仓库根目录执行以下只读命令，或用本机已有等价的 Python 环境。标准输出只包含汇总；可选参数 `--local-case-ids` 将用于本地核对的题标识写到标准错误。

```bash
set -o pipefail
base=reports/qamc_contextual_match_v2_20261112
driver="$base/evo_qamc_fit_v1/run.sh"
launcher=$(sed -n '1,/^entry=trial.py/{ /^entry=trial.py/!p; }' "$driver")
bash -c "$launcher
exec ../qamc/.venv/bin/python \"\$1\"" "$driver" "$base/fusion_candidate_tradeoffs_v1/audit.py" |
  cmp - "$base/fusion_candidate_tradeoffs_v1/SUMMARY.json"
```
