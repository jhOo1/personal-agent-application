# 嵌套历史的终答四格诊断

**区分硬约束可达性与软偏好收益。** 在同一 Actor、同一原题、同一评审输入下，加入原生嵌套历史里新增的合法记录，三个含 C 的来源都改善 Match，不论共享历史是否仍可见。三个仅新增 B 的来源在四种曝光下逐题 Match 持平。只保留新增记录未超过完整历史，也未超过归档 IPE-C。这是用已知自然历史变体构造的诊断输入，不是部署方法。

| 分层指标 | 无历史 | 仅共享历史 | 仅新增历史 | 完整历史 | 归档 IPE-C | 归档 RP |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 仅新增 B · Match，3 题 | 9/17 | 9/17 | 9/17 | 9/17 | 9/17 | 10/17 |
| 仅新增 B · OPB / UPB / FM | 2 / 7 / 3 | 6 / 2 / 2 | 4 / 3 / 2 | 5 / 3 / 2 | 见逐题 | 见逐题 |
| 新增含 C · Match，3 题 | 7/20 | 8/20 | 11/20 | 12/20 | 13/20 | 13/20 |
| 新增含 C · OPB / UPB / FM | 3 / 11 / 9 | 5 / 9 / 9 | 9 / 0 / 2 | 9 / 0 / 2 | 见逐题 | 见逐题 |

B 层四臂有两道共同无旗标，仍均为 6/12；C 层三道四臂均无现有旗标。比较各分层可用性时保留分母。归档 IPE-C 和 RP 的生成路径不同，作为外部于本四格的专项参照。六题均已曝光，属于定向开发诊断，评分为项目 GPT-4.1 适配。

## 相同任务上的实际行动

- **健康外卖 `explicit/006`。** 无历史和仅共享历史都在实际可选菜单中推荐鱼虾。两个看到新增历史的版本都要求排除海鲜和相关汤底、调料，同时给出可执行的外卖建议。完整历史仍主打重口味偏好，显示新增的必要限制生效时，无授权偏好也可能继续影响排序。
- **宿舍自学乐器 `explicit/014`。** 无历史和仅共享历史列出可以买的器材。加入冻结的新史后，两稿都把零开支和不添器材作为条件，提供可利用已有物件的练习方案。未独立核验所有平台资源的实时可访问性。
- **新家客厅 `explicit/047`。** 前两格均出现香薰与暖光。两格加入新史以后给出无香、偏冷色的方案，仍通过布局、材质和间接照明实现温馨。这是两条实际条件一起落实的例子。
- **仅新增软偏好。** 江南自驾在无史已经推荐慢路线，父母纪念日礼物的无史稿也给了手写和定制选项。新增历史改变了建议形式和具体细节，不能从三组的持平分断言这些偏好没有价值。聚餐任务的完整史仍以个人饮食风格影响全组推荐，说明提供合法多样性来源不能抵消先前的错配。

只见新增记录的 C 层仍有 9 点 OPB。以外卖题为例，裁判把部分内容与实际未给 Actor 的自助餐、加班和重口味历史联系起来。客厅题中，裁判也将与冷色灯光同时出现的现代感和简洁布局归到未曝光的偏好。真实文本可与多个来源重合；没有证据显示这些原文实际进入请求。此结果说明不能用 OPB 当成记忆暴露的直接度量，不能由此改原分或断言每个判分都错误。

## 取舍与账本

对三个硬约束来源，新增记录在有无共享背景时都改善实际方案与漏用，支持优先研究让真实必要条件进入且被执行。对于只提供软增益的记录，应分别验证其产生了无史答复中没有的任务收益。隔离共享历史在本组未给出 Match 或 OPB 的独立优势，不能把这四格升级为新的通用方法。下一步需要不依赖同题兄弟历史的适用性和约束判断，并与 IPE-C 同题比较；两主一边界的基准分工保持。

24 个 Actor、24 个 Judge，共 48 次真实请求全部成功，200,740 Token，无缺分、未知用量或重发。首次离线预检修正了作用于非纯嵌套行的缺失标记读取，未派发请求。项目旧分和封存均保持。新评分不支持同协议 SOTA 或独立确认。
