# Answer-side entailment for potentially verifiable actions

NLICV uses the completed answer as the premise and semantic constraints as hypotheses for personalization evaluation. Here we take only that direction of inference, use no reference answer, and include a separately worded contrary action hypothesis. The original QAMC subject-NLI experiment instead treated the source as premise and a sentence from the answer as claim. The new test asks whether a binary local witness can detect actual recommendation conflicts even when the answer repeats the correct preference. [NLICV §§ 2.2–2.3](https://arxiv.org/html/2606.16368v1#S2.SS2)

Use existing development answer pairs where behavior has already been documented. Four source groups have one archived positive-action witness and an opposite or no-evidence control; the fifth is a book club with an explicit cat-exposure conflict and a separate uncommitted-venue answer. No synthetic answer, sealed item, score-based candidate preference, or new Actor. The hypotheses are developer-specified for this instrument test. They are not method predictions or author labels, and the screen cannot estimate real-case precision.

Run the pinned local mDeBERTa NLI classifier with the verbatim existing answer as premise. The head condition tests the maximal prefix fitting both hypotheses. The window condition exhaustively covers at-most-384-token groups of complete lines, making decisions on maximum entailment for each hypothesis. A long single line is a separate window and an over-limit input is a failure. Standalone judgments use threshold 0.70 without tuning; if neither or both hypotheses pass, abstain. Score action detection and false positives separately. At least three pairs must separate in the intended direction and neither uncommitted-venue answer nor excluded recommendations may trigger an erroneous positive before any live comparison is considered. Keep all raw probabilities, hashes, disagreements, prior grades and denominators. This preflight measures the instrument and does not change benchmark scores.
