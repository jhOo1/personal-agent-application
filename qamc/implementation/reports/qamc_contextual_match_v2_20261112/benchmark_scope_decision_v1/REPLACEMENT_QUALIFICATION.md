# Replacement benchmarks for testing mixed-evidence use

The PersistBench three-draw extension establishes a repeatable advantage of partial history over giving the same model all the history on one positive gate decision. It does not demonstrate that the partial history was required on that task, because empty history also produced passing answers in all three draws. Both earlier partial-history wins over the group switch also passed with empty history. The strict utility cases are disjoint. To test whether selective use is necessary, a candidate benchmark should require the same delivered answer to retain one consequential history item and limit another. Cases and scores from the three current benchmarks remain assigned and visible.

## Verified options

| Candidate | What it adds | Qualification result |
|---|---|---|
| **CIMemories** | The same recipient-directed message is assessed both for necessary attributes conveyed and for inappropriate attributes revealed. One fact can have opposite labels across two communication contexts. This is the closest alternative for **disclosure**, a narrower claim than controlling a preference's effect on a recommendation. | Author paper, dataset and evaluation code are public. The author reference workflow regenerates GPT-5 consensus labels and uses DeepSeek-R1-0528 to extract disclosed attributes from five answers per context. The public flattened table declares 71,883 attribute-level rows, not that many tasks. Dataset-server filters at the checked release yield zero rows for both binary values in its label column; the generic non-null request timed out. A separate DeepMind runner likewise documents empty labels and substitutes its own models for both labeling and judging. It is operationally plausible as a disclosed adaptation. No original-label, same-protocol route was established. |
| **PairPref** | 1,227 pairs hold the request and preference fixed and change the situation. The free-generation track assesses appropriate use or non-use across the pair. It tests a contextual flip across two answers, rather than the necessity of keeping two distinct pieces of history within one answer. | Author paper and Appendix B name the evaluation file; usable author rows and runnable public evaluation were not independently located in this check. Keep as the strongest candidate for a future applicability-flip claim. |
| **CUPID** | Distinct historical sessions describe matching and conflicting contextual preferences. Its contrastive and changing settings could test whether a system resolves which preference is currently active. | The author data service reports 756 instances under the pinned release and exposes the prior-interaction and target-preference schema. The author repository provides response-alignment and preference-inference runners. A careful inference comparison could use it once authorized. The published generation alignment score does not provide a separately measured false-use axis on each delivery. It does not establish the formal writing and task-completion protection currently provided by BenchPreS. |
| **OP-Bench** | A reproducible evaluation of repetition, irrelevant use and sycophancy, with released memory methods, data and evaluator. | Public author repository verified. The over-personalization task mix is predominantly repetition (882/1,700), and its accompanying utility comparison uses LoCoMo. It expands the risk evaluations already present in PersistBench and does not establish mixed utility and risk on the same output. |

The CIMemories evidence is the strongest reason to consider a scope change if the paper specifically becomes about recipient-authorized disclosure. It is not an immediate substitute for either formal expression or recipient-appropriate decisions. Recreating the benchmark's necessary/private labels is itself an evaluation decision. The DeepMind alternative documents 490 prompts, 30 persona-sampled labeling calls per prompt and model changes, for 14,700 labeler calls before the full generation comparison. Native metrics count profile-level violation across five generations and coverage separately. A new scoring adaptation would require frozen common labels for every compared method and should not be compared directly with the original paper numbers. Keep the original three-benchmark experiment assignment and the existing two-primary, one-delivery-boundary paper framing for now.

## Case that motivates the distinction

On the exposed PersistBench group-game case, the original memory contains a participant's severe cat allergy as well as a dietary restriction from a different social group. The selected-history request omits the cat and the allergy. FULL includes them but still makes hosting at home the main plan, with a separate venue only as an option. SELECTED, FULL and RUBRIC all avoid mentioning the unrelated dietary restriction in their saved answers. Reopening the entire source pool on this case therefore did not produce an observed misleading-disclosure error, nor did merely seeing the hard condition ensure the main plan met it. This case motivates separating failure to expose a relevant fact from failure to carry it through to an actual decision. A disclosure benchmark can test whether the wrong information is published; it does not test whether the selected venue is feasible.
