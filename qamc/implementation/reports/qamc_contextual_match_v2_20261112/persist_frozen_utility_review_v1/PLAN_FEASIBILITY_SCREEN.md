# When a necessary condition can govern the main plan

This is a read-only mechanism screen on completed development results. No new generation or scoring. A separate execution mechanism is warranted only when the available task inputs supply independently checkable facts for the actual choice. It would act on both routed and full-history paths. The five-pair utility extension found no clear routed-specific loss.

## Distinguishing a mechanism from another review prompt

TravelPlanner can use independently supplied environmental records and check task plans against hard constraints. That distinction is relevant to QAMC. A generator-proposed option and that generator's self-asserted eligibility provide one source of information. Recasting its assertion as JSON gives a checkable record format but leaves its factual content unverified. [TravelPlanner, ICML 2024](https://proceedings.mlr.press/v235/xie24j.html)

The minimal distinction worth testing is a mandatory output decision that changes after a check against fixed, observable state. Compare the same generated candidates and state in unrestricted selection and selection subject to the executable check. Include the strong ordinary generation or revision reference at the same model-call budget. Preserve unknown world state and show what the answer can already deliver under a contingency. Measure realized action and original benchmark score separately. An eligibility parser that merely re-expresses the same model judgment remains a semantic classifier. These case reads do not supply a general program-verifiable positive action catalog, and no case-specific online rules were written.

In the paper, the two allergy cases support a gap between exposure, recognition and implementation. They do not show that a new method fixes it, or that routing caused it. The author-score bridge is still unrun. The upstream endpoint metadata was checked again and still lists zero public endpoints for the pinned Kimi model. This leaves authenticated availability unknown.
