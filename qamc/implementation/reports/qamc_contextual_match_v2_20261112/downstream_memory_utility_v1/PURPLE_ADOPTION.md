# PURPLE adoption audit for the next QAMC shared method

Checked the [ACL paper](https://aclanthology.org/2026.acl-long.1467/) and the author repository at [a4daff7c](https://github.com/linfeng-du/PURPLE/tree/a4daff7c106beeef4910a44d2909a612e595474f). New QAMC experiments and model calls in this audit: 0.

## What the implementation does

- During training, a score model gives each record a query-conditioned weight. The rollout sampler repeatedly normalizes the remaining weights and draws without replacement. The sampling weight of a remaining item is not recomputed from the already selected records. The ordered list is supplied to the Actor, where interactions can affect the reward. [Rollout implementation](https://github.com/linfeng-du/PURPLE/blob/a4daff7c106beeef4910a44d2909a612e595474f/src/purple/rl.py#L59)
- The default loss is REINFORCE and the default feedback is reference completion log likelihood. The implementation can instead generate an answer and compare it with a reference through a task metric. Evaluation uses the learned weights' top-k order. There is no learned abstention action in this released fixed-k path. [Default configuration](https://github.com/linfeng-du/PURPLE/blob/a4daff7c106beeef4910a44d2909a612e595474f/conf/purple.yaml#L31) · [Reward calculation](https://github.com/linfeng-du/PURPLE/blob/a4daff7c106beeef4910a44d2909a612e595474f/src/purple/trainer.py#L224) · [Inference](https://github.com/linfeng-du/PURPLE/blob/a4daff7c106beeef4910a44d2909a612e595474f/src/purple/score_model.py#L102)
- Transfer the idea of evaluating a **complete history exposure against the final answer**, including its opportunity cost relative to another exposure. The author method's training, task references, changing retrieval pool, and fixed-k decision are outside the current QAMC contract. There is no same-protocol external PURPLE result for the QAMC panel in the evidence audited here. No upstream source files were copied.

No fold contained a feasible protected rule among its archived answer paths. Repeating either comparison with Plackett–Luce sampling or a new scalar reward alone would not test a distinct mechanism. ## Decision for the next development design

Use task-level abstention as an explicit exposure, keep the evidence order stable, and measure history effects in matched Actor generations before using them to improve a policy. Before freezing the next experiment, use score-free task and source evidence to locate development roots with an observable way to achieve both sides of the tradeoff. The same comparison must include source-presence verification and actual deliverable behavior. The parent gift test must be able to distinguish an implementable handmade option from assigning an interest to the parents. The book-club test must distinguish a cat-free main plan from a cat-free alternative that leaves the invitation inconsistent. BenchPreS should require the deliverable's factual points and a defined observable expression change.

A scientifically relevant comparison needs to hold the selector's evidence and the final Actor fixed and control for effective exposure size. It also needs a strong control that can improve delivery with the same evidence, since a new generation instruction and a new exposure can otherwise be confounded. Keep IPE-C, Strong Gate, and PB_RUBRIC/SELECTED_GEPA as method-level anchors, with native scoring adaptations stated. Old evaluation labels can audit only completed development outcomes. Provider problems remain missing and sealed sources remain untouched. This audit proposes development requirements, with no new policy, performance gain, or SOTA claim.
