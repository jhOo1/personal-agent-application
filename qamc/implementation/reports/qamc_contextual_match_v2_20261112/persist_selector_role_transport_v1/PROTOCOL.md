# Historical context as assistant recall or a user context message

An instruction-hierarchy distinction can change which history the selector treats as controlling even when the numeric IDs and history are identical. [Instruction hierarchy](https://arxiv.org/abs/2404.13208) motivates isolating message roles. [PairPref §F.7](https://arxiv.org/html/2609.34526v1) directly varies memory presentation for selection, so transport itself is an adaptation, not a novelty claim. This experiment applies it before a fixed end-to-end history-use pipeline. There is no weight update or provider-side hierarchy guarantee.

Use the ten already registered exposed roots from the masking comparison (4 SYC, 3 CD, 3 BU). Fix each case's archived selector branch by its original exact route receipt: use that root's registered risk wave, or the previous fresh utility deployment. The prospective selector arms both have an identical system message, untrusted-history prefix, exact JSON memory content, and final identical task message. Only the history message's API role differs: user or assistant. No labels, Judge scores, answers or method names enter selectors. The original selector plus new common Actor is available from the prior full-reminder experiment, with exact Actor and grade hash reuse when possible. That reference is separately labeled rather than an equal-geometry control.

Compile each parsed selection in original order into the exact prior full-history, explicit source allowance Actor. The body and envelope are equal except source permission flags. All candidates stay fixed. Malformed selections remain unknown; they never silently become empty history. Empty is allowed when the selector validly returns it. Identical Actor wires share a physical response, seeded from the frozen prior experiment when the hash and exact payload agree. No new Actor on identical prior wires or score for an already scored identical response. Each fresh answer is evaluated with the fixed GPT-4.1 and Qwen adapters and same full author evidence. No scorer changes or retries of unknown delivery.

Report source selection changes, end-to-end results by category, strict BU protection and missingness. Require a net gain in either risk category corroborated by both Judges on at least two distinct roots without losing a validated necessary action. These exposed roots, one draw, and two scores of the same answers cannot establish generalization, official SOTA, or provider privilege behavior. Maximum 20 selector, 20 Actor and 40 Judge requests. No sealed inputs.
