# Completed-answer acceptance on RPEval

The V2.1 executor bound changes to real text units, but it still proposed unspecific improvements, repeated recommendations, and applied history outside the task. The new mechanism uses the observable effect of a completed edit and its current task grounding as conditions for changing the delivered answer. It checks real optional gains as well as strict requirements.

Use the 24 fixed exposed single-preference tasks and the exact V1 initial draft for each. The two fixed candidates per task are the primary executed FREE and DELTA answers from V2.1, stored before that round's grading. The presentation sensitivity answers do not enter this comparison. For each generator, compare the initial draft with that generator's candidate. Both reviewers receive the same two completed answers and the same original query, fixed facts, context and raw history. Use the same model, budget and answer contract. The initial draft is identified to both reviewers, and the A/B order is chosen by a frozen hash independent of outcomes. The reviewers select an exact answer. They cannot edit it or access score data.

| Generator | Standard whole-answer comparison | Concrete task change and grounding |
| --- | --- | --- |
| FREE | FREE_GENERIC | FREE_EFFECT |
| DELTA | DELTA_GENERIC | DELTA_EFFECT |

Both comparison prompts permit choosing the strongest complete answer when feasibility, legitimate preference use and task delivery improve. EFFECT structures the comparison around the changed task decision, whether the original memory supports that decision for the intended people, the concrete incremental effect and regression checks. The role, issue and actual consequences remain model judgments. Realized score recoveries and regressions diagnose the policy's behavior. The procedural distinction is in what the reviewer compares. It uses a frozen pair of executed answers, whereas earlier edit-scope experiments restricted candidate generation. The strong standard reviewer controls for refusal to make unnecessary changes and the cost of a second call. A difference would evaluate the bundled instructions, rather than separately identifying each criterion.

No Actor or scoring requests are added. For each changed answer, pay for exactly one reviewer invocation in each matched arm on the same service identity. Identical candidates are structural ties and require no call. Failed delivery or missing candidates remain missing. Invalid reviewer JSON falls back to the initial draft and is counted. Recognition of existing candidate metrics uses only exact hash-bound prior grades after selection is locked. If the selected answer has an invalid prior grade, preserve its missing score. No grade is changed or estimated. The actual cap is frozen from eligible pairs.

Primary comparison is the effect reviewer against the standard reviewer on each generation pathway, using the prior historical 22-task allocation. Report same-task common subsets, the all-method intersection, all-24 allocation, and missing-data bounds. Report kept/adopted counts, accepted and missed recoveries and regressions, and OPB, UPB, FM and A/B/C differences. Judge the adapted scores alongside changes in actual answers. A gain beyond the standard reviewer and V1, with meaningful behavior support and no material regression, motivates expansion. This is a diagnostic development replay with live acceptance calls.
