# Repair an executable alternative that bypasses an applicable constraint

Compare a local, executable edit against a strong unrestricted patch with the same review findings. The hypothesis is that finding a concrete contradiction between two actions, then limiting the editable span, improves execution while preserving the correct part of a strong answer. It does not establish that all contradictions come from historical preferences.

## Fixed experiment contract

- Use only the previously exposed 92-case archive. Freeze six RPEval, four PersistBench and two BenchPreS roots by hash within each benchmark, with one case per conservative source group and an explicitly included known PersistBench board-game allergy diagnostic. The source of the shared starting answer is the frozen IPE-C, PB_RUBRIC or Strong Gate path. The task, raw candidate history, actor alias, revision budget, prior answer, review witness and scoring adapter are common to both arms. Author labels, old scores and case identities are absent from the inference payloads. Old scores are used for availability, the shared reference and exact-draft reuse.
- An independent audit request identifies one actually compliant branch and one actual bypass of the same governing constraint. A valid proposal must provide a unique non-overlapping quote from each branch and an exact quote from the current Query or one listed source. A KEEP result reuses the archived answer for both methods. A malformed or unavailable response is missing for both. This checks referential integrity and editable boundaries. Semantic applicability and the accuracy of the witness remain model judgments.
- Proceed to answer revision only if two distinct source groups have structurally accepted witnesses and at least one comes from RPEval or PersistBench. Both arms then see the same audit. The free arm can patch any part of the draft and protect the compliant action. The local arm can either KEEP or replace the single preapproved violating span. It must preserve the remainder exactly. The shared deterministic patch compiler rejects a bad edit rather than hiding it through a fallback. Both arms receive equal decoding limits and calls. Archive KEEP uses no new scoring call.
- Compare actual behavior in both branches first, with original benchmark grades reported separately. Do not advance unless the target issue is actually repaired on at least two different source groups, the revision preserves the observed alternative and other necessary conditions, and it improves at least one primary benchmark measure over both the same-budget control and its frozen baseline without apparent legal-use or delivery costs. Report absence of opportunity, failure and uncertainty explicitly. Any new large-panel or independent claim requires a separate freeze.
- Request ceiling is 12 shared audits, 24 revisions and at most 44 scoring calls. Use the existing journal with exact caching, at least 3.2 seconds between requests within a stage, and no reissue of unknown requests. All raw artifacts stay in the original worktree's private run storage.

## Relation to prior tests

The old two-state RPEval reviewer asked the generator to add or revise a fallback and then rewrite the draft. It reported 44/75 against the archived 42/75, but found no fully protected target repair in four prospectively chosen unresolved steps. This test searches for an existing concrete bypass first and can repair only that specific branch. The earlier DREW patch targets an unsupported global default introduced by a soft preference. It permits related edits in multiple places and does not require a separately observed compliant branch. Candidate quarantine discards blocks from competing drafts before resynthesizing, while this test never discards the rest of the strong baseline. These operational differences require empirical confirmation rather than a novelty claim.
