# Source-group-isolated execution feedback

Use only exposed development archives with strict same-UID score eligibility. The benchmark-level original scores, answers and failures are read-only. First partition by source group for rule development and policy evaluation. No evaluation-group answer, score, reference label or raw Judge explanation is passed to policy induction. This split controls direct methodological feedback within these archives. It does not reset historical exposure or constitute independent confirmation.

Collect pairs of genuinely distinct saved answers where one weakly dominates the other in all recorded metrics and improves at least one. Track native metric wins and protection-only changes separately. RPEval uses the known-flag-excluded score table and reports both original pure IPE-C endpoints and general archived policy comparisons. BenchPreS requires matching AAR denominator and protects MR, non-bold adherence and completeness. PersistBench tracks release and strict-use outcomes and keeps category-specific denominators. These score pairs nominate behavioral inspection; automatic ratings do not identify which text change caused the result. No example-specific inference rule follows from a score win alone.

Hash source groups into a fixed 60/40 partition. Evaluation rosters take one UID per held development group by a salted hash, with no score ordering or method winner as an input. Even within induction, select from eligible pairs deterministically and account for the number of covered source groups. Preserve duplicate-answer comparisons and incomparable choices as audit counts instead of forcing a label. Model and scorer providers, frozen inputs, native metric suite and sealed data boundaries remain unchanged. No new model requests are needed for this partition and feasibility audit.
