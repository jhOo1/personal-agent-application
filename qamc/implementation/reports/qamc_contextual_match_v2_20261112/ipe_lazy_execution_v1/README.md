# Lazy IPE-C generation cost on the exposed RPEval panel

Predict the IPE ranking for every visible candidate in one call. If any top rank is C, obtain the MLE ranking in one additional call and pass both estimates to the original RP aggregation and Actor. Otherwise call the original task-only Actor immediately. The program adapter accepts the existing request/validation callbacks. read_orders must verify candidate coverage and IDs before exposing the ordered strategies. An invalid estimate remains an error. This implementation applies to the nonempty candidate protocol tested here.

We recovered the switch for 295 of 300 development tasks from the individual IPE rankings, matched it to the frozen branch, and checked available answer hashes against that branch. Five routes are unknown. On the 274 tasks where all three endpoints have a Match score, history is enabled 125 times and disabled 149 times. Cold nominal generation cost is 673 requests versus 822 for full RP (149 fewer, 18.1%). On this same intersection their archived Match totals are 953 and 824 out of 1462. Always empty scores 874 and takes 274 nominal calls. Across all 295 identifiable routes, 727 calls are needed versus 885.

These counts describe successful logical execution from scratch, excluding grading, retries, and shared caches. This read-only replay used zero new model calls. It supplies neither observed token savings nor a wall-clock speedup. The enabled branch executes two estimators sequentially; full RP can run them concurrently. Five unknown routes cannot be assumed free. The exposed-panel results do not establish independent efficacy.
