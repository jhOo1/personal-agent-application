# NRO 开发面板冻结

复用已曝光、有强稿及有效归档评分的开发库存。RPEval 从端点归档取样并排除上一轮诊断组，按作者 A/B/C 分层与已固定路由分配，每组只取一题。作者标签仅用于取样和评价，不进入生成。BenchPreS 和 PersistBench 从既有 TATR 非定向库存取样，分别以画像与来源为组。候选按固定哈希排序，组不跨分割，也不在基准内重复。封存集未读取。

| 每组分割 | 搜索 | 组外开发验证 |
|---|---:|---:|
| RPEval | 9，6 有史／3 无史 | 9，6 有史／3 无史 |
| BenchPreS | 4 个画像 | 4 个画像 |
| PersistBench | 7 个来源组 | 7 个来源组 |

RPEval 的两侧各含全 A、仅 B、含 C 各 3。无史端点作为固定保护对照，只有 17 题每侧具备策略干预机会。此面板是对本轮搜索隔离的开发验证，外部确认资格尚未建立。

私有 ROSTER.json 包含逐条标识、组、历史路径与答案哈希，公开导出只含选择程序及聚合设计。已通过重复生成一致性检查，无模型与评分请求。下一步接入原生评分和同预算优化执行器；此处尚无优化成绩。
