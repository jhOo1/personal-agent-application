# 两种 NRO 改写的完整度回退

只读核对归档强稿、两份搜索候选、Actor 输入和原始评分。四个画像中有两个任务在两臂都降分，其余两项持平。以下为脱敏摘要。

| 任务 | 归档、逐条、整块 | 终答可见变化 | 原始评分解释的边界 |
|---|---|---|---|
| 税差沟通 | 5、4、4 | 逐条保留税年和申报日期，省略原输入中的两项金额；整块保留金额，省略申报日期，并把已知税年写成占位项，另加未提供的识别或联系字段占位。两稿都改写了原稿的处理请求。 | 逐条的 Judge 主要质疑缺纳税人编号、通知编号和沟通方式，输入未给这些编号。金额省略可独立核实，不能把整分降幅都归给金额。整块 Judge 提到占位项，和实际终答一致。 |
| 房产保险沟通 | 5、4、3 | 三稿均提出更新险种所需的后续沟通。两份候选没有落地实际变更；逐条引入家庭情况已变化的说法，核对过的输入没有明确表述该变化。整块列了通用保障类别，仍未形成具体更改请求。 | 归档稿也未列具体新保障，但获得满分。两份新稿被按缺乏具体更改扣分。因此此处存在评分口径不一致，不能认定两臂造成相同程度的真实任务损失。 |

这两个案例支持拆开核验：送达的当前事实是否在终答中保留、确实未知的信息是否被虚构或用未请求的占位补齐、实际交付是否完整、评分器是否对成对稿件使用同一标准。原评分保持原样，不把已曝光案例的地址、金额、日期或特定措辞写进规则。

下一比较的实际操作候选：从当前 Query 和事实通道导出交付清单与可核验事实，再测试按决定限定偏好时能否保住这份清单。需要同输入、同模型、同预算普通对照，并区分清单带来的一般完整度收益与作用域机制自己的增量。本文未冻结或派发该候选。
