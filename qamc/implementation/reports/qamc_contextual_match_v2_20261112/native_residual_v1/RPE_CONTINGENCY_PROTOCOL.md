# RPEval contingency side test

The treatment asks one Actor to solve a still-feasible draft step under two observable execution conditions. Preserve it in the normal condition and replace it only when an already applicable constraint makes it infeasible. The control makes one ordinary strong review call and can produce exactly the same fallback. Both can directly correct a known violation. DREW instead looks for an already unsupported shared default in the old answer and emits an executable atomic patch. This test revises the complete draft once, with no new data, route, retrieval, classifier or call upstream. It does not test a general replacement for IPE-C.

The archived IPE-C branch is the common initial answer. Only the review instruction differs between the two new requests. Model alias, decoding, source text, observed policy, original Query, facts and draft are identical. Exact original Actor and draft SHA-256 values are checked. Each root uses a hashed order to interleave arms. Historical IPE-C is a quality reference without the extra call. Use the existing adapted GPT-4.1 RPEval score and parser, preserve prior grades and delivery states, and never infer individual positions from an aggregate grade. Limit this side test to 24 Actor and 24 Judge calls without old-failure replay.

## Panel and frozen predictions

One case per conservative source group. All 12 are exposed development cases, none from the 15 source groups screened as possible positive repairs. Case strata were manually identified from existing requests and drafts before new generation. Author labels validate sampling only. A failed pair stays missing. There is no replacement draw.

The first stratum contains two related restaurant decisions, an on-trip food decision nested under a route, and a studio choice. That is a feasibility-directed, exposed sample, not representative development sampling. Each action still needs a text-level check. A decline to name an unverified business is compatible with a concrete selection-and-replacement rule. A warning, a redundant branch or an unrelated optional idea is insufficient.

## Decision

On common strict Match, report all three methods with OPB, UPB and FM separately and split out each stratum. Use fixed answer inspections against the table before interpreting ratings. Require at least two unresolved-execution roots where the treatment improves actual execution relative to both archived IPE-C and ordinary review, and require aggregate Match improvement over both, without new observed constraint loss, soft preference hardening, invented assumptions or material deliverable loss. Record missing blind judgments. If repair appears only in the automatic rationale, retain the original scores and leave behavioral qualification unresolved. This is an exposed, one-draw development side test. No general performance, SOTA or protocol-equivalence claim follows.

Use the dependency path in [source-local re-entry](../source_local_reentry_v1/ELIGIBILITY.md) and the existing Python environment with the repository's dependencies. The `check` action of `run_rpe_contingency.py` verifies the roster and both requests without contacting a model; the `run` action uses the archived service reference and existing ledger. Private inputs are required for both.
