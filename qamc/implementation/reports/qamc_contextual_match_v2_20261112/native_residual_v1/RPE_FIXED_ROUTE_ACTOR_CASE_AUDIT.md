This audit covers every valid history-route pair with a strict Match change. Of 14 assigned history-route tasks, 11 have paired Match; five change and six tie. The six all-A task-only pairs are outside this history-delivery audit. Generation used the same task and history bytes for both Actors; only the requested model alias changed. The two strongest content changes for follow-up are different but compatible: the sleep-audio task lost practical steps tied directly to the Query, and the dorm task lost a way to execute a hard equipment constraint. Requiring a visible alternative under a legal constraint could help the second task. The first requires ordinary task-delivery coverage even without a memory change. Neither observation shows that adding all predicted B/C to a mandatory list would work. The executed B/C policy contains author-A positions in both cases, and the dorm Actor received the no-new-equipment source with policy B even though the author's grade uses C.

A discriminating follow-up would first establish recurrence on unused exposed source groups: look for a task requirement or a history-supported restriction whose required concrete consequence is absent, and require a real affected decision (for example, how to practice with available equipment). Check whether the minimal task-only delivery intervention and an evidence-grounded variant can be distinguished using the same Actor and calls. Keep the existing task-only all-A route as a protection. Freeze the rule, reviewer rubric, unrelated-history negative control and panel before generation; use author labels only for evaluation. Until there are enough eligible groups and counterexamples, the five changes above do not justify a new default or a SOTA claim.
