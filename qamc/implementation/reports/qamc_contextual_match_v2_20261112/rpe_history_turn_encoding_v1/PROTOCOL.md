# Speaker turns in implicit RPEval history

Use the frozen IPE-C history route with original task, evidence, RP policy, backbone, output cap, and grading. Off-route tasks still return their saved answers. This experiment tests whether exposing historical speaker roles through the chat API improves use of legitimate constraints without increasing the adoption of an assistant's prior suggestions. Chat interfaces distinguish roles before generation. [Qwen chat templates](https://github.com/QwenLM/Qwen3/blob/main/docs/source/getting_started/concepts.md)

Both test arms carry the same original characters plus identical record IDs, system boundary instruction, and final user message with Query, context, facts and policy. Control puts the historical blocks into one separate user message. Treatment splits at explicit speaker markers and supplies the roles in the message structure, without removing their textual marks. The test is a deployment-format comparison, including message boundaries, not an isolated role-token effect. Original RP serialization remains an archival third comparison. Direct requests are sampled contemporaneously, one draw per arm; no score-based endpoint selection.

Require valid implicit development roots with archived IPE-C history-on answer and strict score. Reject records without an initial user marker or with model control delimiters. Require exact reconstruction of the complete ordered text through concatenation. Select up to three B-only, four C-bearing and two all-A roots in fixed hash order, at most one per source group. Report allocation, replay, incomplete units, Match, OPB, UPB, FM, task integrity and examples of actual usage changes. Expansion needs a positive comparison against both the generated control and the original IPE-C reference, no worsened aggregate severity, two different source groups with observed legal-use improvements and no clear all-A use regression. No retries, pointwise post-hoc output choice, or sealed access.
