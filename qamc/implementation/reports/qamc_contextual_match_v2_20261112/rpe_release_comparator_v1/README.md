# RPEval 发布入口与项目比较的边界

在作者提交 0f8bce80 中，generation_task/eval_multi.py 调用模板时传入预测策略，但根目录 prompts_715.py 的实际生成模板未使用该值。对发布的 150 道显式题、150 道隐式题，把同题预测从全 A 换成全 C 后，300 个生成提示逐字相同。隐式轨道同样取 persona 字段，150 题均与本项目使用的 implicit_persona 内容有别。此结论仅适用于核验的入口。论文机制的项目重建与直接运行该入口须分别标识。

复查 12 题两个固定端点的 24 份发布版短评分回执，全部有六个数值字段，均无逐位 Match。IPE-C 复用所选端点评分。无史端点与完整历史端点的 UPB 严重度总和，项目适配为 25 和 7，发布短评分为 29 和 50，方向发生变化。论文应分别展示两种协议。现有逐位 Match 无法据此直接对标作者发布成绩。

AGGREGATE.json 为可公开汇总。audit.py 从原研究目录读取固定作者 Git 对象及私有归档 rpeval_released_judge_bridge_v1/RESULTS.json。两项核验均为离线操作。
