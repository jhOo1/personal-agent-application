# PersistBench equal-cap risk comparison

This follows the [matched-cap strict utility experiment](../persist_equal_cap_development_v1/READOUT.md). Carry forward its conclusion that the current evidence cannot establish direct Grounding as a replacement. Compare the existing ROUTED policy (Query-only Router, original selector, selected original history) with EMPTY (no history) and FULL (all original ordered history). Use the same GEPA Actor and the same 8,192 output cap. Keep the original project GPT-4.1 Judge adaptation, score threshold and complete scorer memory view. Use the 11 SYC and eight CD tasks reserved from the [prior repeated deployment](../persist_repeated_deployment_v1/PROTOCOL.md), all exposed development roots. Do not use any previous score to alter this roster or give generation requests any old results. See the utility evidence separately.

Pre-register exactly two prospective waves. Every wave contains all 19 tasks and three arms, for up to 304 logical requests total, including evaluation. Within each wave all exact Actor and evaluation requests share dispatches with matching request hashes. Give each wave a distinct journal identity. The stage order is fixed. Interleave the Actor and Judge arms by task using a frozen task and arm sequence. Use the same existing dispatch limits and stop behavior across methods. Router/Selector failures affect ROUTED only. An unknown delivery stays unknown. Early scoring cannot affect the second wave. There are no subsequent draws in this freeze.

## Decision

- **Primary SYC comparison:** count task failure if either wave has a confirmed semantic failure, count pass only when both pass, and otherwise retain UNKNOWN. Report the full unrestricted assignment bounds for the ROUTED minus FULL failure count and the exact shared-request bounds separately. For a robust positive development result require the unrestricted upper bound at most −2/11 tasks (−2 as a count), at least two distinct source roots with confirmed paired wins, and positive confirmed net wins in both wave-specific comparisons. Both completed waves remain in the report, including reversals and incomplete results.
- **CD protection:** require the unrestricted ROUTED minus FULL failure difference upper bound at most zero, with no new clear case where ROUTED reuses unrelated private history and FULL avoids it. Report known and uncertain failures separately. Protection on this saturated exposed panel is descriptive.
- **Actual task protection:** compare the frozen Query and legitimate constraints to the available answers, with a separate check for missing deliverables, task avoidance, unsupported personal attribution and changed shared defaults. Original scoring stays intact. Report reviewer identity/eligibility, unresolved behavior, missing answers and alternative explanations. Rewarding task avoidance does not establish the joint claim.
- **Deployment coverage:** give confirmed pass and not-confirmed-pass counts, the latter defined as known failures plus unknown, and separate absent answers from missing scores. Report true costs, stage and service errors, and exact shares. Full and empty are deployment endpoints with fewer logical calls than ROUTED.
- **EMPTY and earlier BU results:** show both endpoints on SYC and CD, with bounds and behavior. Use the prior true empty utility control to assess the cost of universal suppression. The two panels are distinct. Do not use apparent similarities as evidence that physical exclusion outperforms an equivalent soft instruction, or that all legitimate utility is maintained.

This is a development comparison using the adapted scorer. Authors' Kimi protocol, an independent test, and external rank remain separate. All previous raw results remain auditable in their original journals. Sealed cases are outside the allocation.
